# Reproducing the paper

Every number, table and figure of the paper is regenerated by a script from the result files that
are versioned in this repository. Rerunning an experiment needs the raw datasets, which are not
redistributed here.

## 1. Environment

- Python 3.11 or newer and [uv](https://docs.astral.sh/uv/).
- `uv sync --all-packages` installs the workspace (`packages/snq-*`) and the development tools.
- The learned-mask experiment (E15) also needs PyTorch: `uv sync --all-packages --group learn`. It
  was run on a CUDA GPU; every other experiment runs on CPU.
- Checks: `uv run ruff check .`, `uv run mypy`, `uv run pytest`.

## 2. Datasets

Download each benchmark into the directory that the experiment configurations expect
(`data_dir`). Each manifest in `datasets/manifests/` records the source URL, the licence, the
sampling rate, the bearing geometry and, where available, checksums.

| Benchmark | Directory | Manifest | Licence |
|---|---|---|---|
| University of Ottawa, time-varying speed (Huang and Baddour, 2018) | `datasets/raw/ottawa/` | `ottawa2018.yaml` | CC BY 4.0 |
| Case Western Reserve University, 48 kS/s drive end | `datasets/raw/cwru/` | `cwru.yaml` | public download |
| Paderborn University KAt DataCenter (Lessmeier et al., 2016) | `datasets/raw/paderborn/` | `paderborn.yaml`, `paderborn.sha256` | CC BY-NC 4.0 |
| MAFAULDA (E21 only) | `datasets/raw/mafaulda/` | `mafaulda.yaml` | not declared by the source |

For Paderborn, `datasets/scripts/paderborn_download.sh` downloads the archives,
`datasets/scripts/extract_rar.py` extracts them, and `paderborn.sha256` verifies the files.

## 3. Experiments

Each experiment directory holds its README (design, hypotheses written before the runs, results),
its configurations in `config/`, its code and its versioned results in `results*/`. The general
form of a run is:

```bash
uv run python experiments/<experiment>/<script>.py --config experiments/<experiment>/config/<config>.yaml
```

| Experiment | Paper section | Scripts and configurations |
|---|---|---|
| E07 order estimation on Ottawa | rate wall (Where the method fails) | `run.py` with `base.yaml`, `extended.yaml` |
| E20 folding-zone rejection on Ottawa | decimation valley, mitigations, robust selectors | `run.py` with `base.yaml`, `post_despike.yaml`, `post_median.yaml`, `selectors.yaml`; `recovery.py` |
| E23 injected interferer on CWRU | injected interference | `run.py` and `analyze.py` with `base.yaml`, `spikes.yaml`; `paper_numbers.py` |
| E24 replication on Paderborn | replication on Paderborn | `run.py` with `base.yaml`, `post_despike.yaml`, `ceiling_notch.yaml` |
| E26 fault-order rule on Paderborn | fault-order rule and acquisition | `run_paderborn.py` + `analyze_paderborn.py` (`paderborn.yaml`); `run_paderborn_rule.py` + `analyze_paderborn_rule.py` (`paderborn_rule.yaml`); `run_paderborn_acq.py` + `analyze_paderborn_acq.py` (`paderborn_acq.yaml`) |
| E15 learned sampling masks | power gate, learned masks | `power_gate.py`, `paderborn_gate.py`; `run.py` with `base.yaml` (Ottawa) and `paderborn.yaml` |
| E21 MAFAULDA, E22 equal-rate baselines, E25 co-prime pilot | appendix ledger, failure cases | `run.py` (`base.yaml`), `analyze.py`, `pilot.py` |

Each run writes a `manifest.json` next to its results, with the seed, the package versions, the
SHA-256 of the configuration, of the entry script and of every input file, and a combined SHA-256
of the package sources (`packages/*/src/**/*.py`, scheme recorded in the manifest).

## 4. Numbers, tables and figures of the paper

The scripts in `papers/shared/figures/` read the versioned result files:

```bash
uv run python papers/shared/figures/num_partA_ottawa.py       # and the other num_*.py -> papers/mssp-2026/numbers/
uv run python papers/shared/figures/tab_guided_paderborn.py   # and the other tab_*.py -> papers/mssp-2026/tables/
uv run python papers/shared/figures/fig_partA_valley.py --ruler nested
uv run python papers/shared/figures/fig_partA_paderborn.py
uv run python papers/shared/figures/fig_rule_paderborn.py
uv run python papers/shared/figures/fig_masks_paderborn.py
```

The two last figure scripts recompute every plotted point from the per-segment results and stop if
a point differs from the analysis file of the run. Exploratory analyses cited in the paper have
their own scripts, named in the text (for example `experiments/E20-fold-zone-rejection/exploratory/spike_train.py`
and `experiments/E15-learned-sampling-mask/explore_line_split.py`).

## 5. The paper PDF

`papers/shared/build_pdf.py` installs a minimal TeX Live (TinyTeX) inside `.tools/`, without
touching the system PATH, and builds the paper. The source archive of a release, which is what its
Zenodo record keeps, leaves out the manuscript text, so build the PDF from a clone of the
repository:

```bash
uv run python papers/shared/build_pdf.py install
uv run python papers/shared/build_pdf.py build papers/mssp-2026 --submission
```

## 6. Provenance and pre-registration

The hypotheses, decision rules and tests of each experiment were written in its README before the
run. Appendix A of the paper lists every pre-registered hypothesis with its verdict and says whether
it was committed before the run. This repository keeps the git history of the files it contains, so
the commit that holds each pre-registration, and the file versions whose hashes a manifest records,
can be checked out. The comments, docstrings and READMEs were translated from Portuguese to English
after the runs; the versions referred to by the manifests are those in the earlier commits.

This repository was extracted from the authors' working repository, keeping only the released
paths, so every commit has a new hash. Old versions of a few exploratory scripts hard-coded the
absolute path of the authors' working copy; in this history it reads `<repository root>`. The commit hashes cited in the READMEs and in the code were
rewritten to the new ones. The `git_sha` field of each `manifest.json` keeps the original hash, and
`COMMIT_MAP.tsv` maps every original commit to its commit here (or marks it as not included, when
it touched only files that are not released).

The labels that the runs wrote into the result files (arms, cleanings, rulers, verdicts) were
Portuguese words and were renamed to English after the runs, by `tools/relabel_results.py` with
the map in `tools/relabel_map.py`. The renaming replaced the labels and nothing else, so every
number is the one the run wrote. The code derives its random seeds from the original labels, so a
rerun draws the same random numbers. The files as the runs wrote them, whose hashes the analysis
files record, are those of the earlier commits, and they can also be rebuilt from the current ones:

```bash
uv run python tools/relabel_results.py --invert --check    # rebuild each original in memory, check its hash
uv run python tools/relabel_results.py --invert --out DIR  # write the originals under DIR
```

`tools/relabel_record.json` holds, for every result file, its hash before and after the renaming
and what the inversion needs. `GLOSSARY.md` explains the labels.

The `git_dirty` field of a few smoke-run manifests lists files of the authors' working repository
that are not released here. They are kept as the runs recorded them.
